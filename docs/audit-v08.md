# Аудит v0.8 — свежий read-only проход (v0.9 Фаза 0, 2026-07-26)

Метод тот же, что в audit-v07: каждое заявление прогона v0.8 (CHANGELOG
0.8.0, docs/handoff.md, ADR-021, docs/audit-v07.md, чеклист v8) сверено с
фактическим выводом инструмента ЭТОЙ сессии. В CONFIRMED попадает только

Традиция аудитов: v0.1 — незанулённая passphrase, v0.2 — фантомные тесты,

## MISCLASSIFIED

1. **Вывод о рантайме подан шире, чем позволяла единственная
   проверенная ячейка.** Формулировки v0.8 — CHANGELOG «the shipped
   default engine **refuses the file**», чеклист v8 «§0.8 … **ОТВЕЧЕН**,
   ответ ОТРИЦАТЕЛЬНЫЙ» — читаются как вердикт о движке. Фактически было
   проверено **одно сочетание**: tasks-genai × Qwen2.5-1.5B q8
   × контейнер `.litertlm`. Из одной ячейки нельзя различить три разные
   причины отказа (контейнер / токенизатор / конкретный файл), а разница
   между ними меняет продуктовое решение целиком.
   Сам ADR-021 аккуратнее (называет развилки и метит гипотезу про int4
   как UNVERIFIED), но производные тексты потеряли эту осторожность.
   → Разрешено экспериментом Фазы E этого прогона; см. **ADR-022**.
   Классификация: не выдумка, а **сверхобобщение одной точки данных**.

2. **«Внешнее свидетельство» про контейнер не подтвердилось источником.**
   Постановка v0.9 просила проверить веб-поиском тезис, что браузерный
   `@mediapipe/tasks-genai` распознаёт только магию TFL3 и игнорирует
   LITERTLM. Поиск 2026-07-26 выдал утвердительный ответ, но при
   прослеживании он опирается на `.tmp-research-query.md` в постороннем
   репозитории `emilyLi2020/WAVE` — то есть на черновик исследования
   другого агента, а не на источник. Авторитетного подтверждения не
   найдено: единственный релевантный issue Google —
   [mediapipe-samples#468](https://github.com/google-ai-edge/mediapipe-samples/issues/468)
   (открыт 30.09.2024, **закрыт без ответа мейнтейнеров**) — говорит о
   **бандлере** («Qwen2.5 doesn't provide Tokenizer model file»), не о
   рантайме, и потому подтверждает исходную посылку ADR-018, а не тезис
   о контейнере.
   → Тезис остаётся **гипотезой** и проверяется экспериментом, а не
   поиском. Записано здесь, чтобы «в интернете подтвердилось» больше не
   всплыло как основание.

## DEGRADED

1. **Чеклист v8 §0 обещает владельцу проверку, которая теперь дешевле
   делается без него.** Пункт «САМОЕ ЦЕННОЕ, что можно сделать на
   телефоне сейчас: переиграть Фазу D на живом железе» был верен, пока
   единственным препятствием считалась RAM эмулятора (2 ГБ против модели
   1.6 ГБ). Препятствие снято средой: AVD с 8 ГБ создаётся на этой
   машине, и Фаза E прогоняет матрицу без телефона.
   Дефект не в факте, а в адресате: владельцу оставлена работа, которую
   агент может сделать сам. → чеклист v9 переписывает §0, оставляя
   владельцу только то, что действительно требует Exynos 2400 (скорость
   и качество), и снимая с него вопрос «читается ли файл вообще».

2. **Лицензионное расхождение оставлено владельцу с формулировкой,
   которая переоценивает риск.** Чеклист v8 §2-НОВОЕ ставит вопрос
   «какое число юридически полное» так, будто 192 может быть неполным
   набором, то есть дырой в атрибуции. Проверка Фазы L этого прогона
   показала инструментом, что дыры нет ни одной (0 из 35 дельты
   присутствует в release-графе), и вопрос владельцу был не нужен.
   → закрыто Фазой L, чеклист v9 снимает пункт.

## Побочный результат: у Qwen существует контейнер `.task`

Аудит проверял размер и по дороге уперся в факт, опровергающий посылку,
на которой стоял весь спор о токенизаторе. ADR-018 писал: «Qwen2.5 has no
SentencePiece tokenizer → the legacy `.task` bundler is blocked (issue
#275)». Листинг HF API 2026-07-26 (`?blobs=true`, репозиторий
`litert-community/Qwen2.5-1.5B-Instruct`, `gated: False`):

```
1598556720  Qwen2.5-1.5B-Instruct_multi-prefill-seq_q8_ekv4096.task
1597931520  Qwen2.5-1.5B-Instruct_multi-prefill-seq_q8_ekv4096.litertlm
```

То есть `.task`-контейнер для Qwen **существует и опубликован officially
by litert-community**, ровно того же размера класса, что и `.litertlm`.
Посылка «для Qwen .task невозможен» устарела. Это открыло Фазе E
эксперимент, которого постановка не предполагала и который оказался
решающим: подать один и тот же токенизатор в двух контейнерах.
